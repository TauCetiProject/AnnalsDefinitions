# 26. Normalized Nash blowup

## Status
PREREQS-ROADMAPPED. Not a target anywhere; it is #25 followed by Mathlib's normalization, so it inherits #25's status (Grassmannian of a coherent sheaf planned in merged SchemeAndStackFoundations §4.14 and open PR #853 §1.3).

Depends on #25.

## Mathlib
- Relative normalization `AlgebraicGeometry.Scheme.Hom.normalization`, `toNormalization`, `fromNormalization`, universal property `normalizationDesc`, `normalization.hom_ext` (`Mathlib/AlgebraicGeometry/Normalization.lean`); compatibility with disjoint unions and smooth base change.
- Everything listed under #25 (Grassmannian functor, smooth locus, scheme-theoretic image).

## Tau Ceti code
- Normalization API extensions: `TauCeti/AlgebraicGeometry/Normalization/` (e.g. `isRegular_normalization_fromSpecStalk_genericPoint`), finiteness still a hypothesis.
- Everything listed under #25. No Nash or normalized Nash blowup.

## Merged roadmaps
- Not a target. Prerequisites as for #25; plus SchemeAndStackFoundations §0.20 (Japanese/Nagata rings: finiteness of normalization for finite-type `k`-algebras, needed for 26.1's finiteness; STATUS: hard Nagata results missing) and §0.30 normal schemes (complete).

## Open roadmap PRs

## Prerequisite chain
1. Nash blowup `(X^*, ν)` (#25): unplanned (prerequisites in code, the coherent Grassmannian implicitly in merged §4.14 as Quot with `X = S` (not started), explicitly in PR #853 §1.3).
2. Normalization of a reduced scheme: Mathlib `Scheme.Hom.normalization` applied to `∐ Spec κ(ξ_i) → X^*` (in Mathlib).
3. Finiteness of normalization for finite-type `k`-schemes: SchemeAndStackFoundations §0.20 (merged, partially implemented).
4. Smoothness of the normal locus in codim 1 etc. (26.3(a)): mostly Mathlib/Tau Ceti.
5. Iterates `Y_i` and "resolves singularities": unplanned, trivial once 1–3 exist.

## Library-scale gap
Same section as #25. For the paper one also needs normal affine toric varieties as schemes over `k` (`Spec k[σ^∨ ∩ M]`) and their Nash blowups via logarithmic Jacobian ideals. Toric varieties exist only analytically (Completed/AnalyticToricGeometry); an algebraic toric-varieties roadmap would sit beside SchemeAndStackFoundations. References: Cox–Little–Schenck, *Toric varieties*; González Pérez–Teissier.
